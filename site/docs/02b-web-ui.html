goose ui                 # open it at http://127.0.0.1:7777
goose ui --tailscale     # also reachable from your phone over your tailnet
goose ui --update        # pull the latest partiality first
goose ui --no-open       # start the server without opening a browser
goose ui stop            # stop the background server

The server runs in the background, so your terminal comes straight back. Its log is ui.log in gooseneck's runtime dir.

partiality is a web UI for gooseneck in Material 3 Expressive, with dark, AMOLED and light themes. It's a remote: music plays on the machine running goose ui, through the same player the TUI and CLI control, so they all stay in sync.

What's in it

Home, library, artist and album pages, queue, history, stats, downloads, synced lyrics (tap a line to seek) and settings. / focuses search, Esc closes menus and the full-screen player.

Where it lives

If partiality isn't installed, goose ui says what it will clone and where, and asks before doing it (it needs git; --yes skips the question, and without a terminal it refuses rather than guess). It goes into <config dir>/partiality. To serve another checkout:

goose config set ui ~/code/partiality

If the server is already running, goose ui just opens the browser.

On your phone

--tailscale also listens on this machine's tailnet IP and MagicDNS name. There's no login: your tailnet decides who can reach it. It never listens on 0.0.0.0, and requests with an unknown Host or a foreign Origin are refused.

The API underneath

goose ui is goose serve --ui <dir> --open, in the background. goose serve on its own is a JSON API for everything the CLI does, plus live player state over server-sent events at /api/events:

goose serve                                  # API only
goose serve --ui ~/my-ui --addr 127.0.0.1:8080
curl -s 127.0.0.1:7777/api/now | jq .track.title
